## Durable Memory Notes

- `_workspace/**` is local runtime output only. It must not define policy, methodology, progress state, durable memory, or final governed deliverables.
- `docs/00.agent-governance/memory/` owns active methodology, active progress, and durable agent memory.
- `docs/00.agent-governance/policy-change-log.md` owns versioned governance, SDLC protocol, runtime contract, and validator changes.
- `docs/00.agent-governance/sdlc-workflow.md` owns stable human-agent collaboration flow and baton-passing checkpoints.
- `00.agent-governance/sdlc-workflow.md` without the `docs/` prefix is docs-relative shorthand only. It must not be created as a root-level directory or separate authority surface.
- `00_System/sdlc-workflow.md` is not a Project-Template governance path and must not duplicate or override Stage 00 workflow, memory, or policy records.
- Active methodology is run-state memory, not a standalone policy store; allowed methodology choices and hard stops are governed by Stage 00 rules and templates.
- Security CI intentionally uploads a short-retention `gitleaks-report` artifact; workflow role validation must allow and require `actions/upload-artifact` for `ci-security.yml`.
- QA test strategy authority is `docs/03.specs/<feature-id>/tests.md` from `tests.template.md`; execution plans own runnable validation strategy and execution tasks own evidence.
- Active runtime references should point to `docs/LLM-WIKI.md`; `root LLM-WIKI.md` is stale wording in this compact docs model.
- `docs/90.references/` is a release-template skeleton on `main`; generated navigation must not be restored there. `docs/LLM-WIKI.md` remains the canonical AI operating summary.
- `.github` workflow and metadata base-template validation can pass while `python3 scripts/validation/validate-github-metadata.py --strict-derived` fails on unresolved derived-project placeholders. Treat strict-derived as a downstream activation gate until real owner, repository, and security-contact values are supplied.
- Hook policy belongs in `.claude/hooks/**`, `.claude/settings.json`, Stage 00 governance, and validators. Do not restore `.codex/hooks.json` or add GitHub-native instruction files for hook policy.
- `bash scripts/ws.sh hook <event> [matcher]` is the provider-neutral local execution path for configured command hooks. Claude Code consumes `.claude/settings.json` directly; Codex, Gemini, and other local agents should use the `ws hook` dispatcher instead of adding a second hook policy file.
- `.agent-work/phase-gate.toml` and `.agent-work/skill-map.md` are prompt-package handoff controls outside `docs/`; they do not override Stage 00 governance, root routers, or provider runtime settings.
- `RTK.md` is optional local Codex CLI guidance. Normal repository commands, Git commands, and `bash scripts/ws.sh ...` validation examples remain valid without `rtk`.
- `scripts/qa/summarize-tdd-coverage.sh --fail-on-missing` is part of `bash scripts/ws.sh validate`; plain `bash scripts/qa/summarize-tdd-coverage.sh` remains a report-only direct helper.
- `docs/05.operations/` is the compact Stage 05 storage root for operations documentation, while its subfolders preserve stage-gate semantics: guides map to Stage 07, policies to Stage 08, runbooks to Stage 09, and incidents/postmortems to Stage 10.
