# Compliance & Audit Hub

> [!NOTE]
> This directory was migrated to `docs/00.agent-governance/compliance/` to comply with the 8-folder compact governance policy.

## Overview

This directory records optional project-level compliance and audit guidance for derived projects that need regulatory readiness. The source template stays stack-neutral and keeps only reusable compliance boundaries here.

## Audience

This README is for compliance owners, security reviewers, and agents that need to decide where audit evidence or privacy policy material belongs.

## Scope

### In Scope

- SOC 2 readiness prompts for derived projects.
- Privacy-by-design guidance for PII handling.
- Audit evidence categories that can be created per project.

### Out of Scope

- Legal advice or jurisdiction-specific policy text.
- Active product privacy policies for a derived project.
- Incident runbooks, which belong in `docs/05.operations/runbooks/` or `docs/05.operations/incidents/`.

## Structure

| Area | Purpose |
| :--- | :--- |
| Regulatory Frameworks | Reusable compliance prompts for derived projects. |
| Evidence Library | Audit artifact categories to collect when the project adopts them. |
| Future Documents | Per-project compliance documents that may be added later. |

## How to Work in This Area

1. Confirm the compliance requirement belongs to the template and is not project-specific legal text.
2. Add governed documents only when a derived project needs durable compliance records.
3. Keep any new document linked from the `Documents` table and relevant Stage 08/10 operational evidence.
4. Run `python3 scripts/validation/validate-doc-readiness.py` and `bash scripts/validation/validate-cross-links.sh` after changing this folder.

## Regulatory Frameworks

### SOC 2 Type II Readiness

- **Security**: Require encryption for data at rest and in transit when the derived project stores sensitive data.
- **Availability**: Link availability evidence to Stage 08 metrics and SLO documentation.
- **Confidentiality**: Define role-based access control in the derived project's operational policy.

### Privacy

- **GDPR/CCPA**: Define data subject request handling when the project processes regulated personal data.
- **Data Minimization**: Limit personal data collection to the approved product purpose.

## Evidence Library

- **SBOM**: `_workspace/audit/sbom.json` when generated by `bash scripts/ws.sh sbom`.
- **Security Audits**: `bash scripts/ws.sh audit` output when stack manifests exist.
- **Access Logs**: Derived-project monitoring or audit-log dashboards.
